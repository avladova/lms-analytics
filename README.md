# LMS Analytics: исследование образовательных данных

> **Цель проекта:** повысить эффективность образовательного процесса за счёт воспроизводимой образовательной аналитики данных LMS: от проверки качества выгрузок и статистических гипотез до ранних риск-сигналов, сегментации траекторий и педагогических рекомендаций.

Проект использует анонимизированные выгрузки результатов по математическим дисциплинам за 2022/23–2024/25 учебные годы. Его результатом должны быть не только модели и дашборды, но и **объяснимые, этически допустимые решения** для преподавателя, учебного подразделения и разработчика курса.

## Исследовательская логика

Работа с LMS-данными строится как последовательность **«источник → качество и нормализация → аналитический признак → модель/сегмент → педагогическое действие → оценка эффекта»**. Число кликов, тестов или вероятность риска не являются самостоятельным доказательством обучения; они формируют сигнал, который должен быть проверен в контексте дисциплины и поддержан педагогическим действием. Методологические требования и ограничения изложены в [методологии](docs/methodology_ru.md) и [обзоре литературы](docs/literature_review_ru.md).

| Направление | Вопрос | Минимальный результат |
| --- | --- | --- |
| Качество данных | Сопоставимы ли задания, попытки и шкалы разных выгрузок? | Версионируемые словари и паспорт источника |
| Описательная аналитика | Где возникают разрывы в выполнении и освоении? | Профили по дисциплине, группе и периоду |
| Ранний прогноз | Кому может быть полезна своевременная поддержка? | Временно валидированный, калиброванный риск-сигнал |
| Сегментация | Какие устойчивые профили учебной траектории существуют? | Интерпретируемые кластеры и анализ устойчивости |
| Вмешательство | Улучшает ли действие преподавателя учебный результат? | Протокол пилота и оценка эффекта |

## Быстрый старт

Для структурного аудита корректированных файлов используйте Python 3.11+ и `openpyxl`. Команда ничего не меняет в исходных XLSX-файлах и создаёт только профиль их структуры.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/profile_lms_workbooks.py \
  --input-dir data \
  --pattern '*_correct.xlsx' \
  --output-dir artifacts/data_profile
```

Для анализа в R используйте сценарии из `development/R/` как шаблоны, заменив локальные абсолютные пути на путь внутри репозитория. Новый код должен принимать путь как параметр и не зависеть от рабочего стола конкретного пользователя.

## Правила работы с данными

| Правило | Практическое требование |
| --- | --- |
| Выбор источника | Для сравнительного исследования использовать версии `*_correct.xlsx`; исходные файлы сохранять как архивные источники. |
| Происхождение | Фиксировать имя файла, ветку/коммит, хеш, период и версию словаря. |
| Пропуски | Различать неназначенное задание, отсутствие попытки, нулевой результат и техническую ошибку. |
| Повторные попытки | До анализа задать правило первой, последней, лучшей или иной попытки. |
| Публикация | Не выгружать индивидуальные траектории, списки риска, ключи сопоставления или малые группы. |

## GitHub Project и рабочий процесс

На [LMS dashboard](https://github.com/users/avladova/projects/3/views/1) следует вести задачи по потоку **Backlog → Ready → In progress → In review → Done**. Подготовленная конфигурация полей, представлений и исследовательских карточек приведена в [плане доски](docs/github_project_plan.md). Изменения репозитория создаются только в отдельных ветках и попадают в `main` через проверяемый Pull Request.

## Материалы и отчёты

Техническое задание сохранено в [`docs/Тех задание.txt`](docs/%D0%A2%D0%B5%D1%85%20%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5.txt). Научные материалы в `report/` дополняются [реестром источников](docs/sources_manifest.md), который связывает проектные статьи, публичный набор данных и внешнюю литературу. Базовый HTML-прототип дашборда находится в ветке [`dashboard`](https://github.com/avladova/lms-analytics/tree/dashboard); он должен развиваться через отдельные задачи и PR.

## Лицензия и участие

Лицензия для кода и данных пока не установлена. До появления явной лицензии запрещено считать данные свободными для повторного использования. Для предложения аналитической задачи используйте шаблон **Research task**, описывая вопрос, источник, временной срез, валидацию и запланированное педагогическое действие.
