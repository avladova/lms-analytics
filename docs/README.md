# Документация исследования

Документация отделяет неизменяемое техническое задание от воспроизводимых правил работы с данными и аналитическими результатами. При конфликте между новым экспериментом и требованиями ниже приоритет имеют защита данных, трассируемость происхождения и отсутствие утечки будущей информации.

| Документ | Содержание | Когда использовать |
| --- | --- | --- |
| [`Тех задание.txt`](Тех%20задание.txt) | Исходная постановка НИР, этапы и ожидаемые результаты | Для проверки соответствия работ целям НИР |
| [`data_catalog.md`](data_catalog.md) | Инвентаризация корректированных файлов, правила выбора и ограничения | До загрузки/объединения выгрузок |
| [`methodology_ru.md`](methodology_ru.md) | Протокол нормализации, моделирования и вмешательств | До создания признаков и моделей |
| [`literature_review_ru.md`](literature_review_ru.md) | Тематический обзор проектных и внешних источников | Для обоснования гипотез и публикаций |
| [`sources_manifest.md`](sources_manifest.md) | Реестр использованных источников | Для прослеживаемого цитирования |
| [`github_project_plan.md`](github_project_plan.md) | Поля, представления и стартовые карточки LMS dashboard | Для наполнения GitHub Project |

> Результаты новых экспериментов должны храниться в `report/` только в агрегированном и безопасном для публикации виде. Обязательные реквизиты отчёта: вопрос, версия данных, период, правило попыток, дата среза, валидация, ограничения и ссылка на код.
