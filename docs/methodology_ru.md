# Методология воспроизводимого анализа LMS-данных

## Цель и границы применения

Цель аналитики — сформировать **объяснимый ранний сигнал** для педагогической поддержки, а не автоматическое решение о студенте. Анализ должен различать уровень студента, группы, потока, дисциплины и образовательной программы. Итоговое решение всегда принимает специалист, знакомый с контекстом курса и обстоятельствами обучающегося.

## Пайплайн исследования

| Этап | Действие | Контроль | Артефакт |
| --- | --- | --- | --- |
| 1. Фиксация источника | Выбрать `*_correct.xlsx`, записать ветку, SHA, период и владельца | Источник воспроизводим | Реестр источников |
| 2. Профилирование | Прочитать листы, размеры, заголовки, типы и пропуски | Ошибки и аномалии не скрываются | Паспорт файла |
| 3. Нормализация | Применить словари работ и тем | Для каждого сопоставления есть версия словаря | Журнал преобразований |
| 4. Выбор попытки | Определить правило первой, последней или лучшей попытки | Правило едино для сравниваемой выборки | Таблица попыток |
| 5. Конструирование признаков | Рассчитать показатели только на дату среза | Нет будущей информации среди признаков | Матрица признаков |
| 6. Модель / сегментация | Сравнить baseline и дополнительные методы | Временное разбиение и анализ ошибок | Model card / отчёт |
| 7. Вмешательство | Связать сигнал с действием поддержки | Измеряется эффект, соблюдается этика | Протокол пилота |

## Нормализация данных

Заголовки выгрузки LMS не являются стабильными ключами. Исходное имя активности должно быть сохранено вместе с нормализованным кодом, типом работы, темой и версией словаря. Объединение должно быть детерминированным и повторяемым: новые варианты названий добавляются через версионируемый словарь, а не через ручные замены непосредственно в таблицах.

Пропуск, нулевой балл, неназначенное задание и технически неизвестное значение имеют разный педагогический смысл. Значения не следует автоматически заменять нулём. Для каждого статуса рекомендуется явное кодирование.

| Ситуация | Кодирование | Интерпретация |
| --- | --- | --- |
| Работа не назначалась | `assigned_flag = 0` | Не входит в знаменатель завершённости |
| Работа назначена, попытки нет | `assigned_flag = 1`, `attempted_flag = 0` | Возможная задержка после проверки контекста |
| Попытка есть, балл 0 | `attempted_flag = 1`, `score = 0` | Реальный результат, а не пропуск |
| Несколько попыток | Отдельные записи попыток | Сведение выполняется по правилу исследования |
| Неизвестное / ошибка | `quality_flag` | Исключается или исследуется отдельно |

## Признаки, цели и временная логика

Признак разрешается использовать только тогда, когда он был доступен на момент построения прогноза. Итоговая оценка, поздние пересдачи и данные после даты среза не должны попадать в раннюю модель. Перед запуском эксперимента нужно зафиксировать целевую переменную, период, дату среза и набор допустимых источников.

Полезные базовые группы признаков включают долю назначенных и выполненных заданий, своевременность, ранние нормированные оценки, динамику результатов, устойчивость выполнения и флаги качества данных. Не допускается одновременно использовать один показатель как признак и как часть целевой переменной.

## Валидация и интерпретация

Основной метод оценки переносимости — **временная валидация**: обучение на более раннем учебном периоде и проверка на последующем. Случайное разбиение строк допустимо лишь как дополнительная диагностика. Для бинарного риска минимум сравниваются логистическая регрессия и нелинейная модель; оцениваются recall, precision, ROC-AUC, PR-AUC, калибровка и ошибки по дисциплинам/группам. Для непрерывного результата применяются MAE, RMSE, R² и анализ остатков.

Кластеризацию следует использовать для выявления профилей, а не для скрытого прогнозирования. K-means, иерархическая кластеризация и DBSCAN сравниваются несколькими критериями качества; полученные кластеры проверяются на устойчивость при альтернативной обработке пропусков и интерпретируются с экспертами дисциплины.

## Педагогическое вмешательство и этика

Модельный сигнал должен быть связан с заранее определённым допустимым действием: проверкой технического барьера, приглашением на консультацию, разъяснением дедлайна, подбором материала для повторения. Он не используется для санкций, публичного ранжирования или автоматического ограничения возможностей студента.

Каждый пилот фиксирует получателя сигнала, ответственного, действие, период, метрику эффекта и ограничение. Эффект следует оценивать по следующей доступной контрольной точке — например, выполнению обязательного задания или прогрессу в теме — с учётом учебного дизайна и различий когорт.

## Минимальное содержание отчёта

Отчёт в `report/` должен включать исследовательский вопрос, единицу наблюдения, период и версию источников, словарь и правило попыток, дату среза, признаки и целевую переменную, схему разбиения, метрики, анализ ограничений и описание педагогического действия. Такой формат позволяет отличить технический эксперимент от доказательства управленческой полезности.
